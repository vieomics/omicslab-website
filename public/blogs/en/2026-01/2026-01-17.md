Pixi is a package manager built on the conda ecosystem. It installs into user space, so it can be used on a personal laptop or on a shared HPC cluster where administrator rights are unavailable. This note is a short primer: installation, cluster configuration, and the commands we use most often to pin a reproducible environment.

For a worked example of the same approach applied to a full analysis, see [Setting up single-cell RNA-seq analysis with Pixi](https://ngs101.com/setting-up-single-cell-rna-seq-analysis-environment-with-pixi-10x-faster-setup-zero-version-conflicts/), written as a collaboration between RIVERXDATA and NGS101.

## Installing Pixi

### System requirements

- **Operating system**: any modern Unix (Ubuntu, Debian, CentOS, Fedora, Arch, macOS, …)
- **Disk space**: roughly 50–100 MB for Pixi itself, plus room for packages and the cache
- **Privileges**: none — Pixi installs entirely in the user's home directory

This is convenient on shared systems where `sudo` is not available.

### One-line installation

```bash
curl -fsSL https://pixi.sh/install.sh | bash
```

The script installs Pixi into `~/.pixi/bin` and updates the shell configuration. Restart the terminal, or reload the shell:

```bash
source ~/.bashrc  # or ~/.zshrc
```

### Verifying the installation

```bash
pixi --version
pixi --help
```

## Configuring Pixi on an HPC cluster

### Custom cache location

Home directories on clusters often have a small quota. Pointing the cache at scratch space avoids filling it:

```bash
export PIXI_CACHE_DIR=/scratch/$USER/pixi-cache
```

Add the line to `~/.bashrc` or `~/.bash_profile` to make it persistent.

### Proxy settings

When the cluster reaches the internet through a proxy, configure it in `$HOME/.pixi/config.toml`:

```toml
[proxy-config]
http = "http://proxy.example.com:8080/"
https = "http://proxy.example.com:8080/"
non-proxy-hosts = [".cn", "localhost", "[::1]"]
```

See the [Pixi configuration reference](https://pixi.prefix.dev/latest/reference/pixi_configuration/) for the remaining options.

### Parallel downloads

On a fast network, a small increase in concurrency can shorten environment creation:

```toml
[concurrency]
downloads = 5
```

## Project environments

Pixi records a project's tooling in `pixi.toml` and locks exact versions in `pixi.lock`.

### Initializing a project

```bash
pixi init
pixi workspace channel add conda-forge bioconda
pixi workspace platform add osx-arm64 linux-64
```

An example `pixi.toml`:

```toml
[workspace]
channels = ["bioconda", "conda-forge"]
name = "<your project>"
platforms = ["linux-64", "osx-arm64"]
version = "0.1.0"

[tasks]

[dependencies]
```

### Adding tools

```bash
pixi add fastqc multiqc
```

This updates the dependencies in `pixi.toml`:

```toml
[dependencies]
fastqc = ">=0.12.1,<0.13"
multiqc = ">=1.17,<2"
```

Pixi also writes `pixi.lock`, which records the exact package versions and checksums so the same environment can be rebuilt later.

### Running tools

Tools can be run directly:

```bash
pixi run fastqc --help
```

Or from an activated environment:

```bash
pixi shell
fastqc --help
```

## Summary

- Pixi installs in user space, so it works on laptops and on HPC clusters without administrator rights.
- Installation is a single command; the cache and proxy settings can be adjusted for cluster constraints.
- `pixi.toml` and `pixi.lock` keep environments reproducible across machines and over time.
- Tools are added and removed without modifying the system environment.
