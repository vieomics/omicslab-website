Workflow Description Language (WDL) đang được cộng đồng bioinformatics quan tâm nhiều hơn như một lựa chọn thay thế Nextflow cho các pipeline tính toán tái lập được. Nếu bạn đã làm việc với Nextflow và muốn tìm hiểu WDL, nhiều khái niệm sẽ quen thuộc, và một số khác biệt về cú pháp cũng như mô hình thực thi đáng để lưu ý. Hướng dẫn này đi qua việc thiết lập WDL với miniWDL và Sprocket — hai executor WDL hiện đại — đồng thời so sánh với Nextflow.

<!--truncate-->

## 1. Hiểu WDL so với Nextflow: mô hình executor

Khác biệt chính giữa WDL và Nextflow không chỉ nằm ở cú pháp — mà còn ở cách workflow được thực thi. Sự khác biệt này quan trọng khi chọn công cụ.

### 1.1 Mô hình thực thi

**Nextflow** vừa là ngôn ngữ **vừa** là runtime executor. Bạn viết bằng Nextflow DSL2 và thực thi trực tiếp bằng CLI `nextflow`, vốn trừu tượng hóa khác biệt hạ tầng:

```bash
nextflow run workflow.nf -profile slurm   # HPC with SLURM
nextflow run workflow.nf -profile aws     # AWS Batch
nextflow run workflow.nf -profile k8s     # Kubernetes
nextflow run workflow.nf -profile azure   # Azure
```

**WDL** chỉ là ngôn ngữ — bạn cần một executor riêng để chạy. Các executor phổ biến gồm Cromwell, miniWDL và Sprocket, mỗi cái có cấu hình và khả năng riêng:

```bash
miniwdl run workflow.wdl -i inputs.json              # Local/Simple
sprocket run workflow.wdl inputs.json                # Modern CLI
java -jar cromwell.jar run workflow.wdl              # Enterprise
```

### 1.2 So sánh hệ sinh thái và độ trưởng thành

| Khía cạnh                      | WDL                                             | Nextflow                                              |
| ------------------------------ | ----------------------------------------------- | ----------------------------------------------------- |
| **Ngôn ngữ vs Runtime**        | Chỉ ngôn ngữ (cần executor riêng)               | Ngôn ngữ + runtime tích hợp (CLI nextflow)             |
| **Mô hình thực thi**           | Task khai báo + tổ hợp workflow                 | Kênh dựa trên dataflow                                |
| **Hệ thống kiểu**              | Kiểu mạnh, xác thực lúc biên dịch               | Kiểu yếu, linh hoạt lúc chạy                           |
| **Nguồn gốc & cộng đồng**      | Broad Institute (Mỹ), cộng đồng đang lớn dần     | Nguồn gốc châu Âu, hiện được dùng rộng rãi            |
| **Hỗ trợ cloud**               | Cromwell/Sprocket trên AWS, GCP, Azure (đang lên) | Hỗ trợ trưởng thành trên các cloud lớn              |
| **Hỗ trợ HPC**                 | Cromwell/miniWDL trên SLURM, PBS, v.v.          | Hỗ trợ sẵn cho SLURM, PBS, SGE                        |
| **Kubernetes**                 | Hỗ trợ hạn chế                                  | Hỗ trợ K8s trưởng thành                               |
| **Triển khai production**      | Cấp doanh nghiệp trên Cromwell/Terra            | Được dùng rộng rãi trong production                   |
| **Workflow cộng đồng**         | ~500+ (GATK, WILDS)                             | Hơn 10.000 workflow công khai                         |
| **Đường cong học tập**         | Dốc hơn (cấu trúc chặt hơn)                     | Thoải hơn (trực quan hơn)                             |
| **Linh hoạt hạ tầng**          | Cách tiếp cận đa executor (kém thống nhất)      | Một CLI với trừu tượng profile (rất linh hoạt)        |

### 1.3 Khi nào chọn cái nào

**Chọn WDL khi:**

- ✓ Làm việc trong hệ sinh thái Broad Institute (Terra, FireCloud)
- ✓ Kiểm tra kiểu nghiêm ngặt và xác thực lúc biên dịch là ưu tiên
- ✓ Xây dựng thư viện task module để dùng lại (best practice của GATK)
- ✓ Quản trị doanh nghiệp yêu cầu xác thực workflow chính thức
- ✓ Tổ chức của bạn đã có hạ tầng Cromwell

**Chọn Nextflow khi:**

- ✓ Cần linh hoạt và lặp nhanh
- ✓ Cần định tuyến dữ liệu động, phức tạp
- ✓ Muốn truy cập các bộ sưu tập workflow cộng đồng lớn (hơn 10.000 workflow công khai)
- ✓ Chạy trên nhiều hạ tầng khác nhau (cloud + HPC + K8s) từ một codebase
- ✓ Tổ chức của bạn theo cloud-native hoặc đa nền tảng
- ✓ Ưu tiên cấu hình executor đơn giản (chỉ đổi `-profile`)
- ✓ Cần tính di động và tái lập tối đa giữa các môi trường
- ✓ Xây dựng để được dùng rộng rãi (phần lớn nhà nghiên cứu dùng Nextflow)

## 2. Thiết lập môi trường

### 2.1 Cài miniWDL

miniWDL là một executor WDL nhẹ, hướng đến phát triển và kiểm thử cục bộ:

```bash
# Using pip (Python 3.8+)
pip install miniwdl

# Verify installation
miniwdl --version

# Or using conda
conda install -c bioconda miniwdl
```

### 2.2 Cài Sprocket

Sprocket là một executor WDL hiện đại với giao diện CLI:

```bash
# Install using curl
curl -L https://releases.sprocket.bio/sprocket/latest/sprocket-linux-x86_64 -o sprocket
chmod +x sprocket
mv sprocket /usr/local/bin/

# Or download from: https://sprocket.bio/

# Verify installation
sprocket --version
```

### 2.3 Cài Docker hoặc Apptainer

Workflow WDL dựa trên môi trường container. Chọn một trong hai:

```bash
# Docker (recommended for local development)
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# Or Apptainer (HPC environments)
sudo apt-get install apptainer
```

## 3. Workflow WDL đầu tiên

Một workflow "Hello World" đơn giản minh họa cấu trúc cơ bản:

```wdl
version 1.0

task greet {
    input {
        String name
    }

    command <<<
        echo "Hello, ~{name}!"
    >>>

    output {
        String greeting = read_string(stdout())
    }

    runtime {
        docker: "ubuntu:22.04"
        memory: "512 MB"
        cpu: 1
    }
}

workflow hello_world {
    input {
        String person_name = "World"
    }

    call greet { input: name = person_name }

    output {
        String message = greet.greeting
    }
}
```

### 3.1 Các khái niệm WDL chính

- **`version 1.0`**: phiên bản đặc tả WDL (giống manifest của Nextflow)
- **`task`**: tương đương `process` của Nextflow, định nghĩa một đơn vị tính toán
- **`workflow`**: điều phối các task và luồng dữ liệu (giống workflow block của Nextflow)
- **`input`**: tham số đầu vào có kiểu tường minh (kiểu mạnh, khác Nextflow)
- **`command`**: lệnh shell (giống block `script:` của Nextflow)
- **`runtime`**: đặc tả container và tài nguyên (giống `container` và `resources` của Nextflow)
- **`output`**: output khai báo tường minh kèm kiểu

## 4. Chạy workflow đầu tiên

### 4.1 Tạo tệp inputs JSON

Tạo `hello_inputs.json`:

```json
{
  "hello_world.person_name": "WDL User"
}
```

Chú ý cú pháp: `workflow_name.input_parameter`.

### 4.2 Chạy với miniWDL

```bash
# Run the workflow
miniwdl run hello_world.wdl -i hello_inputs.json

# Check outputs in the generated directory
cd hello_world_*/
cat outputs.json
```

### 4.3 Chạy với Sprocket

```bash
# Run with Sprocket
sprocket run hello_world.wdl hello_inputs.json

# Sprocket provides a summary
sprocket run hello_world.wdl hello_inputs.json --watch
```

## 5. Ví dụ thực tế: định lượng RNA-seq

Một ví dụ thực tế là pipeline `ww-sra-salmon` từ [WILDS WDL Library](https://github.com/getwilds/wilds-wdl-library), tải dữ liệu RNA-seq từ Sequence Read Archive của NCBI và định lượng mức phong phú transcript bằng Salmon.

### 5.1 Kiến trúc pipeline

```
sra_salmon workflow:
├── Download FASTQ from SRA (scattered across samples)
├── Detect paired-end vs single-end
├── Build Salmon index (once)
├── Quantify transcripts (scattered quantification)
└── Merge results into expression matrices
```

### 5.2 Workflow chính

```wdl
version 1.0

import "https://raw.githubusercontent.com/getwilds/wilds-wdl-library/refs/heads/main/modules/ww-sra/ww-sra.wdl" as sra_tasks
import "https://raw.githubusercontent.com/getwilds/wilds-wdl-library/refs/heads/main/modules/ww-salmon/ww-salmon.wdl" as salmon_tasks

workflow sra_salmon {
  meta {
    author: "Taylor Firman"
    description: "Download RNA-seq from SRA and quantify with Salmon"
  }

  input {
    Array[String] sra_id_list
    File transcriptome_fasta
    Int ncpu = 8
    Int memory_gb = 16
    Int? max_reads
  }

  # Build Salmon index (single task, not scattered)
  call salmon_tasks.build_index {
    input:
      transcriptome_fasta = transcriptome_fasta,
      cpu_cores = ncpu,
      memory_gb = memory_gb
  }

  # Process each SRA sample in parallel (scatter)
  scatter ( id in sra_id_list ){
    call sra_tasks.fastqdump {
      input:
        sra_id = id,
        ncpu = ncpu,
        max_reads = max_reads
    }

    # Conditional: paired-end vs single-end handling
    if (fastqdump.is_paired_end) {
      call salmon_tasks.quantify as quantify_paired {
        input:
          salmon_index_dir = build_index.salmon_index,
          sample_name = id,
          fastq_r1 = fastqdump.r1_end,
          fastq_r2 = fastqdump.r2_end,
          cpu_cores = ncpu,
          memory_gb = memory_gb
      }
    }

    if (!fastqdump.is_paired_end) {
      call salmon_tasks.quantify as quantify_single {
        input:
          salmon_index_dir = build_index.salmon_index,
          sample_name = id,
          fastq_r1 = fastqdump.r1_end,
          cpu_cores = ncpu,
          memory_gb = memory_gb
      }
    }

    # Select output from appropriate branch
    File quant_dir = select_first([quantify_paired.salmon_quant_dir, quantify_single.salmon_quant_dir])
  }

  # Merge quantification across all samples
  call salmon_tasks.merge_results {
    input:
      salmon_quant_dirs = quant_dir
  }

  output {
    Array[File] salmon_quant_dirs = quant_dir
    File tpm_matrix = merge_results.tpm_matrix
    File counts_matrix = merge_results.counts_matrix
  }
}
```

### 5.3 So sánh với Nextflow

Cùng logic đó trong Nextflow DSL2:

```groovy
// Nextflow equivalent (simplified)
workflow sra_salmon {
  input_ch = Channel.fromList(params.sra_id_list)

  build_index(file(params.transcriptome_fasta))

  input_ch
    | fastqdump
    | quantify
    | collect
    | merge_results
}
```

**Khác biệt chính:**

- `scatter` của WDL tường minh và giới hạn phạm vi; kênh của Nextflow động hơn
- `if` của WDL cho điều kiện tường minh; Nextflow dùng `when` và phân nhánh
- `import` của WDL kéo task từ xa trực tiếp; Nextflow dùng `include` và đường dẫn cục bộ
- WDL yêu cầu khai báo kiểu input/output tường minh; Nextflow ngầm định hơn

## 7. Các tính năng chính của WDL

### 7.1 Scatter (song song hóa)

`scatter` của WDL tường minh và an toàn về kiểu:

```wdl
scatter (sample in sample_list) {
  call process_sample { input: sample_name = sample }
}
# Output is automatically collected into an Array
Array[File] results = process_sample.output_file
```

**So với Nextflow:**

```groovy
sample_ch = Channel.fromList(sample_list)
sample_ch | process_sample
```

### 7.2 Điều kiện

```wdl
if (fastqdump.is_paired_end) {
  call quantify_paired { ... }
}

# Select output safely
File result = select_first([quantify_paired.output, quantify_single.output])
```

### 7.3 Hệ thống kiểu

WDL áp đặt kiểu nghiêm ngặt:

```wdl
# These won't compile
Int my_int = "string"  # ERROR
File f = my_int        # ERROR

# Correct
Int number = 42
File input_file = "/path/to/file.txt"
Array[File] files = ["/file1.txt", "/file2.txt"]
```

### 7.4 Tổ hợp task và import

```wdl
# Import tasks from GitHub
import "https://raw.githubusercontent.com/getwilds/wilds-wdl-library/refs/heads/main/modules/ww-salmon/ww-salmon.wdl" as salmon_tasks

# Use imported tasks with namespace
call salmon_tasks.build_index { ... }
```

## 8. Hiểu về executor WDL so với Nextflow

Phần này trình bày một khác biệt kiến trúc dễ bị bỏ qua.

### 8.1 Trừu tượng hóa executor

**Nextflow: một CLI, nhiều backend**

Với Nextflow, bạn chuyển giữa các backend hạ tầng bằng profile — cùng mã, môi trường thực thi khác:

```bash
# Define once, run anywhere
nextflow run workflow.nf -profile slurm     # Local HPC
nextflow run workflow.nf -profile aws       # AWS Batch + S3
nextflow run workflow.nf -profile azure     # Azure Batch
nextflow run workflow.nf -profile gcp       # Google Cloud
nextflow run workflow.nf -profile k8s       # Kubernetes
```

**WDL: ngôn ngữ cộng executor riêng**

WDL tách biệt các mối quan tâm: viết workflow bằng WDL, rồi chọn executor hỗ trợ hạ tầng của bạn:

- **miniWDL**: phát triển cục bộ, môi trường nghiên cứu
- **Cromwell**: triển khai doanh nghiệp (hỗ trợ HPC, AWS, Google Cloud, Azure)
- **Sprocket**: lựa chọn hiện đại với tính năng hướng cloud
- **dxCompiler**: tích hợp với nền tảng DNAnexus

Mỗi executor cần cấu hình riêng.

### 8.2 So sánh executor WDL

#### 8.2.1 miniWDL

**Phù hợp nhất với:** phát triển cục bộ, lặp nhanh, học tập

**Ưu điểm:**

- Nhẹ, dễ cài (pip)
- Thông báo lỗi và gỡ lỗi chi tiết
- Vòng phản hồi nhanh cho phát triển
- Không cần Docker daemon (có thể dùng `--empty-secondaries`)
- Cài đặt thuần Python

**Hạn chế:**

- Chủ yếu chạy trên một máy
- Không hướng đến workflow production quy mô lớn
- Hỗ trợ HPC tích hợp còn hạn chế

**Sử dụng:**

```bash
miniwdl run workflow.wdl -i inputs.json -d output_dir
miniwdl check workflow.wdl  # Syntax validation
```

#### 8.2.2 Cromwell

**Phù hợp nhất với:** triển khai doanh nghiệp, cụm HPC, genomics quy mô lớn

**Ưu điểm:**

- Chuẩn được thiết lập cho workflow genomics
- Trưởng thành, đã kiểm chứng trong production (hơn 10 năm)
- Hỗ trợ nhiều backend (AWS, Google Cloud, Azure, HPC)
- Tích hợp với hệ sinh thái GATK
- Cơ chế cache job và retry
- Được dùng bởi nền tảng Terra (Broad Institute)

**Hạn chế:**

- Yêu cầu tài nguyên nặng hơn (chạy trên Java)
- Tệp cấu hình phức tạp
- Đường cong học tập dốc hơn miniWDL
- Thời gian khởi động chậm hơn

**Sử dụng:**

```bash
java -jar cromwell.jar run workflow.wdl --inputs inputs.json
```

**Ví dụ cấu hình backend (Cromwell):**

```hocon
backend {
  default = "slurm"

  providers {
    slurm {
      actor-factory = "cromwell.backend.impl.sfs.config.ConfigBackendLifecycleActorFactory"
      config {
        runtime_attributes = """
          Int cpu = 1
          Int? memory_gb
          String? docker
        """
      }
    }
  }
}
```

#### 8.2.3 Sprocket

**Phù hợp nhất với:** triển khai cloud hiện đại, phát triển tương tác

**Ưu điểm:**

- Kiến trúc hướng cloud
- CLI có theo dõi tiến độ
- Cài đặt bằng một binary
- Có cache và tối ưu hóa sẵn
- Tích hợp với các nền tảng cloud

**Hạn chế:**

- Dự án mới hơn (hệ sinh thái đang hình thành)
- Ít triển khai production hơn Cromwell
- Hỗ trợ backend HPC còn hạn chế (đang phát triển)

**Sử dụng:**

```bash
sprocket run workflow.wdl inputs.json --watch
sprocket validate workflow.wdl  # Type checking
```

### 8.3 So sánh: executor WDL so với Nextflow

| Tính năng          | miniWDL        | Cromwell        | Sprocket  | Nextflow       |
| ------------------ | -------------- | --------------- | --------- | -------------- |
| **Local Dev**      | ✓ Excellent    | ○ Works         | ✓ Good    | ✓ Excellent    |
| **HPC (SLURM)**    | ✗ No           | ✓ Yes           | ○ Limited | ✓ Native       |
| **AWS Batch**      | ✗ No           | ✓ Yes           | ✓ Yes     | ✓ Native       |
| **Google Cloud**   | ✗ No           | ✓ Yes           | ✓ Yes     | ✓ Native       |
| **Azure**          | ✗ No           | ✓ Yes           | ✓ Yes     | ✓ Native       |
| **Kubernetes**     | ✗ No           | ○ Limited       | ✓ Yes     | ✓ Native       |
| **Installation**   | ✓ Simple (pip) | ○ Requires Java | ✓ Simple  | ✓ Simple       |
| **Configuration**  | ○ JSON         | ✗ Complex       | ✓ Simple  | ✓ Config files |
| **Learning Curve** | ✓ Gentle       | ○ Steep         | ✓ Gentle  | ✓ Gentlest     |

**Điểm mấu chốt:** Nextflow xử lý trừu tượng hóa executor ở một chỗ — bạn định nghĩa môi trường thực thi trong tệp config, không phải trong executor. WDL yêu cầu chọn executor khớp với nhu cầu hạ tầng.

## 9. Best practice khi phát triển WDL

### 9.1 Thiết kế task theo module

```wdl
# Good: Reusable, single responsibility
task align_reads {
  input {
    File reads
    File reference
    Int threads
  }
  # ... implementation
}

# Bad: Too many responsibilities
task process_and_qc_and_align {
  # ...
}
```

### 9.2 Dùng struct cho input phức tạp

```wdl
struct Sample {
    String name
    File r1_fastq
    File r2_fastq
}

workflow my_workflow {
  input {
    Array[Sample] samples
  }

  scatter (sample in samples) {
    call process_sample { input: sample_data = sample }
  }
}
```

### 9.3 Tận dụng an toàn kiểu

```wdl
# Compile-time validation catches errors early
File my_file = "/path/to/file.txt"  # Clear intent
Int threads = 8                     # Not a string
```

### 9.4 Dùng metadata

```wdl
task my_task {
  meta {
    description: "What this task does"
    author: "Your Name"
    email: "your@email.com"
  }

  parameter_meta {
    input_file: "Description of input"
    output_name: "Description of output"
  }

  input { ... }
  command { ... }
  output { ... }
}
```

## 10. Khi nào chọn mỗi ngôn ngữ: hướng dẫn thực tế

Quyết định giữa WDL và Nextflow thường phụ thuộc vào hạ tầng, nhóm và nhu cầu cộng đồng hơn là chỉ riêng tính năng ngôn ngữ.

### Dùng WDL khi:

- ✓ **Hệ sinh thái Broad Institute**: làm việc với Terra, FireCloud hoặc hạ tầng Cromwell sẵn có
- ✓ **An toàn kiểu quan trọng**: xác thực lúc biên dịch quan trọng với tổ chức của bạn
- ✓ **Tập trung vào module**: xây dựng thư viện task dùng lại được (như pipeline GATK)
- ✓ **Quản trị doanh nghiệp**: cần xác thực nghiêm ngặt và quản lý workflow chính thức
- ✓ **Tích hợp GATK**: dùng workflow theo best practice của GATK
- ✓ **Phạm vi nhỏ hơn**: workflow được định nghĩa rõ với mẫu thực thi dự đoán được

### Dùng Nextflow khi:

- ✓ **Linh hoạt hạ tầng**: cần chạy cùng workflow trên HPC, AWS, Azure, GCP, K8s
- ✓ **Cấu hình đơn giản**: thích một cờ `-profile` hơn là thiết lập riêng cho từng executor
- ✓ **Cộng đồng**: muốn truy cập hơn 10.000 workflow công khai
- ✓ **Tạo mẫu nhanh**: lặp nhanh mà không tốn chi phí kiểm tra kiểu nghiêm ngặt
- ✓ **Workflow động**: phân nhánh phức tạp, định tuyến có điều kiện hoặc input động
- ✓ **Được dùng rộng rãi**: đi theo workflow engine phổ biến nhất
- ✓ **Đa hạ tầng**: tổ chức của bạn chạy trên nhiều nền tảng
- ✓ **Trưởng thành production**: cần mô hình thực thi đã được kiểm chứng rộng rãi

### Cây quyết định nhanh

```
Does your organization use Cromwell/Terra?
  ├─ YES → Consider WDL + Cromwell
  └─ NO → Consider Nextflow

Do you need to run on multiple infrastructure types from same code?
  ├─ YES → Nextflow (built-in abstraction)
  └─ NO → Either works, consider other factors

Do you want community workflows?
  ├─ YES → Nextflow (10,000+ available)
  └─ NO → WDL or Nextflow

Is infrastructure compatibility your main challenge?
  ├─ YES → Nextflow (cleaner abstraction)
  └─ NO → Choose based on other factors
```

## Tóm tắt

WDL và Nextflow đại diện cho hai cách tiếp cận khác nhau với tự động hóa workflow:

- **Nextflow** là ngôn ngữ cộng runtime executor, trừu tượng hóa hạ tầng qua profile. Nó có cộng đồng toàn cầu lớn, với hơn 10.000 workflow công khai, hỗ trợ đa nền tảng trưởng thành (HPC, AWS, GCP, Azure, Kubernetes) và chuyển cấu hình qua profile.
- **WDL** là ngôn ngữ kiểu mạnh, cần executor riêng (miniWDL, Cromwell, Sprocket). Nó phù hợp với hệ sinh thái Broad Institute (Terra, pipeline GATK), nơi xác thực lúc biên dịch và tổ hợp task chính thức quan trọng. Cromwell hỗ trợ triển khai cấp doanh nghiệp; miniWDL hỗ trợ phát triển cục bộ nhanh.

**Điểm kiến trúc mấu chốt:** trừu tượng hóa executor của Nextflow giúp triển khai đa nền tảng đơn giản hơn — chỉ cần đổi profile. WDL yêu cầu chọn executor khớp với nhu cầu hạ tầng. Với các tổ chức chạy trên nhiều nền tảng, CLI thống nhất của Nextflow là một lợi thế; với các nhóm gắn với Broad Institute, cấu trúc chính thức và tích hợp Terra của WDL có thể là lý do hợp lý để chấp nhận độ phức tạp của executor.

**Khuyến nghị thực tế:**

- **Bắt đầu với Nextflow** nếu bạn muốn được áp dụng nhanh, có workflow cộng đồng và cấu hình hạ tầng tối thiểu
- **Chọn WDL** nếu bạn đã ở trong hệ sinh thái Broad (Terra, GATK) hoặc cần xác thực kiểu nghiêm ngặt
- **Học cả hai** để hiểu khi nào mỗi cách tiếp cận phù hợp

WILDS WDL Library cung cấp các module sẵn sàng cho production giúp tăng tốc phát triển WDL, trong khi dự án nf-core cung cấp hơn 100 pipeline Nextflow đã qua peer review. Dù chọn cách nào, bối cảnh hạ tầng workflow hiện có những công cụ trưởng thành cho genomics tái lập được và có thể mở rộng.
