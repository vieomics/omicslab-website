GitHub Actions là một cách phổ biến để tự động hoá kiểm thử cho một kho bioinformatics, nhưng mỗi lần chạy đều phải push lên GitHub và chờ một runner trên cloud, nên vòng phản hồi tính bằng phút. [`act`](https://github.com/nektos/act) là một công cụ dòng lệnh chạy các workflow GitHub Actions cục bộ bằng Docker, nhờ đó có thể kiểm thử một workflow trước khi push.

Bài viết này trình bày cách cài đặt, những lệnh dùng thường xuyên nhất, cách xử lý secrets và biến môi trường, các Docker image liên quan, và một vài kỹ thuật gỡ lỗi. Các ví dụ là những pipeline chung; cách làm tương tự cũng áp dụng cho một workflow gene-expression hoặc quality-control.

<!--truncate-->

## Vì sao nên chạy workflow cục bộ

Vòng lặp thông thường là:

1. Viết hoặc sửa tệp workflow, rồi push lên GitHub
2. Chờ runner trên cloud nhận job
3. Nếu workflow thất bại, sửa cục bộ rồi push lại
4. Lặp lại bước 2 và 3 nếu cần

Với `act`, bước 2 được thay bằng một lần chạy cục bộ: workflow được thực thi ngay trên máy của người phát triển, nên có thể hoàn thành vài vòng lặp trước khi push bất cứ thứ gì. Thời gian tiết kiệm được tuỳ vào workflow và máy, nhưng lợi ích chính là một workflow bị hỏng thường được phát hiện sớm hơn.

## Phần 1: Cài đặt và thiết lập

### Bước 1: Cài `act` bằng Pixi

Một cách để cài `act` toàn cục là dùng [Pixi](https://pixi.sh), một trình quản lý gói có thể cài cả gói Python lẫn công cụ hệ thống:

```bash
pixi global install act
```

Pixi chọn đúng binary cho hệ điều hành (macOS, Linux hoặc Windows).

Kiểm tra cài đặt:

```bash
act --version
# Output: act version 0.2.X
```

Một số lý do cách này có thể thuận tiện:

- đa nền tảng (macOS, Linux, Windows)
- không cần thêm phụ thuộc hệ thống
- chỉ một lệnh: `pixi global install act`
- cập nhật bằng `pixi global upgrade act`
- tách biệt khỏi Python và các gói của hệ thống
- dùng cùng công cụ để quản lý môi trường dự án

### Các cách cài đặt khác

**macOS (Homebrew)**
```bash
brew install act
```

**Linux**
```bash
# Debian/Ubuntu
curl https://raw.githubusercontent.com/nektos/act/master/install.sh | bash

# Or with pacman (Arch)
pacman -S act
```

**Windows (PowerShell)**
```powershell
choco install act
# Or if using Scoop:
scoop install act
```

**Cài thủ công**
- tải từ trang [GitHub Releases](https://github.com/nektos/act/releases)
- giải nén binary vào một thư mục trong `$PATH`

### Bước 2: Cài Docker

`act` dùng Docker để chạy workflow trong container, tương tự cách runner trên cloud của GitHub làm.

**Cách 1: Docker Desktop**
- tải [Docker Desktop](https://www.docker.com/products/docker-desktop) cho macOS hoặc Windows
- cài đặt và khởi động ứng dụng
- sau đó Docker sẽ có sẵn trong terminal

**Cách 2: Cài các công cụ Docker bằng Pixi**
```bash
# Install Docker tools in your Pixi environment
pixi global install docker
```

**Cách 3: Gói hệ thống trên Linux**
```bash
# Debian/Ubuntu
sudo apt-get install docker.io docker-compose
sudo usermod -aG docker $USER  # Add current user to docker group
newgrp docker  # Activate group changes
```

Kiểm tra cài đặt Docker:

```bash
docker --version
docker run hello-world  # Should complete successfully
```

Gỡ lỗi:
- macOS/Windows: đảm bảo Docker Desktop đang chạy
- Linux: kiểm tra daemon đang chạy bằng `sudo systemctl start docker`
- permission denied: thêm người dùng vào nhóm docker bằng `sudo usermod -aG docker $USER`

### Bước 3: Kiểm tra thiết lập

Kiểm tra rằng `act` tìm thấy các workflow trong kho:

```bash
cd /path/to/your/repo
act --list
```

Kết quả mong đợi:

```
Stage  Job ID  Job Name  Workflow Name     Workflow File           Events
0      test    test      test-workflow     .github/workflows/test.yml  push
```

Nếu không có workflow nào xuất hiện, kiểm tra rằng `.github/workflows/` tồn tại và chứa các tệp `.yml`.

### Bước 4: Tích hợp Pixi (tuỳ chọn)

Nếu dự án dùng Pixi, có thể thêm `act` như một task:

**Thêm vào `pixi.toml`:**
```toml
[tasks]
ci = "act push"
ci-test = "act pull_request"
ci-debug = "act -v push"
```

**Sau đó chạy bằng Pixi:**
```bash
pixi run ci           # Run GitHub Actions locally
pixi run ci-debug     # With verbose output
```

**Kiểm tra thiết lập Pixi:**
```bash
pixi info
# Should show: act is available globally
```

## Phần 2: Sử dụng cơ bản

### Một workflow kiểm thử Python tối giản

Một workflow GitHub Actions nhỏ để thử với `act`:

**Tạo `.github/workflows/test.yml`:**
```yaml
name: Python Tests
on:
  push:
    branches: [main, develop]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.12'

      - name: Install dependencies
        run: |
          pip install pytest numpy pandas

      - name: Run tests
        run: |
          pytest tests/ -v
```

**Chạy cục bộ:**
```bash
act push
```

**Kết quả mong đợi:**
```
[Python Tests/test] 🚀 Start image pull...
[Python Tests/test] 🐳 Docker pull requested ghcr.io/catthehacker/ubuntu:act-latest
[Python Tests/test] ✓ Image pull complete
[Python Tests/test] 🚀 Start container...
[Python Tests/test] ⭐ Run Main actions/checkout@v3
[Python Tests/test] ✓ Complete job
```

### Chạy một workflow hoặc job cụ thể

**Liệt kê các workflow có sẵn:**
```bash
act --list
```

**Chạy một job cụ thể:**
```bash
act --job test
```

**Chạy một workflow cụ thể:**
```bash
act --workflow test.yml
```

**Mô phỏng một sự kiện khác (ví dụ `pull_request`):**
```bash
act pull_request
```

## Phần 3: Biến môi trường và secrets

### Truyền biến môi trường

`act` cung cấp vài cách để truyền biến.

**Cách 1: cờ dòng lệnh**
```bash
act -e event.json
```

Trong đó `event.json` chứa:
```json
{
  "repository": {
    "name": "my-repo",
    "owner": {
      "login": "myusername"
    }
  }
}
```

**Cách 2: tệp `.actrc`** (ở thư mục gốc của kho)
```bash
# .actrc
-P ubuntu-latest=ghcr.io/catthehacker/ubuntu:act-latest
-l
```

**Cách 3: biến môi trường của shell**
```bash
export MY_VAR="value"
export ANOTHER_VAR="another"
act push
```

### Làm việc với secrets

GitHub Actions dùng `secrets` cho dữ liệu nhạy cảm. Với `act`, có thể truyền secrets cục bộ.

**Cách 1: tệp `.secrets`** (ở thư mục gốc của kho)
```bash
# .secrets
MY_SECRET=super_secret_value
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
API_KEY=your_api_key_here
```

Thêm `.secrets` vào `.gitignore` để không bị commit:
```bash
echo ".secrets" >> .gitignore
```

**Cách 2: cờ secret trên dòng lệnh**
```bash
act -s MY_SECRET=value -s GITHUB_TOKEN=token
```

**Một workflow dùng secrets:**
```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Use secret
        run: |
          echo "API Key: ${{ secrets.API_KEY }}"
          echo "Token: ${{ secrets.GITHUB_TOKEN }}"
```

**Chạy với secrets:**
```bash
act --secret-file .secrets
```

:::warning
Ví dụ `echo` ở trên sẽ in giá trị secret ra log. Nó chỉ được nêu để minh hoạ cách tham chiếu secrets; tránh echo secret thật trong một workflow chạy ở bất kỳ đâu ngoài một container cục bộ dùng một lần.
:::

## Phần 4: Docker và quản lý container

### Các image container mà `act` dùng

`act` dùng các Docker image dựng sẵn mô phỏng runner cloud của GitHub. Các image mặc định khá lớn, giúp tăng khả năng tương thích với những công cụ mà workflow mong đợi.

**Các image có sẵn:**
```bash
# Ubuntu (medium size, the default choice)
ghcr.io/catthehacker/ubuntu:act-latest

# Full Ubuntu (largest, closest to a GitHub cloud runner)
ghcr.io/catthehacker/ubuntu:full-latest

# Official Ubuntu (smallest, but only the base system)
ubuntu:latest  # Docker Hub
```

### Chỉ định image

**Cách 1: cờ `-P` trong lệnh**
```bash
act -P ubuntu-latest=ghcr.io/catthehacker/ubuntu:full-latest
```

**Cách 2: tệp `.actrc`**
```bash
# .actrc
-P ubuntu-latest=ghcr.io/catthehacker/ubuntu:full-latest
-P windows-latest=ghcr.io/catthehacker/windows:full-latest
```

**Chọn kiến trúc container**
```bash
act --container-architecture linux/amd64
```

### Kéo sẵn image

Image lớn sẽ mất thời gian trong lần chạy đầu. Có thể kéo trước:

```bash
# Pull the image once
docker pull ghcr.io/catthehacker/ubuntu:act-latest

# Now act will use cached image (much faster)
act push
```

### Quản lý dung lượng đĩa

Docker image chiếm nhiều dung lượng. Có thể xoá các image không dùng:

```bash
# Remove unused images
docker image prune -a

# Remove all containers
docker container prune -a

# Check disk usage
docker system df
```

## Phần 5: Ghi chú về hiệu năng

### 1. Chọn một image nhỏ hơn

Các image `catthehacker` được phát hành với một vài kích cỡ. Image nhỏ hơn kéo và khởi động nhanh hơn nhưng có ít công cụ cài sẵn hơn, nên khởi động có thể nhanh hơn trong khi các bước thiết lập lại lâu hơn.

```bash
act -P ubuntu-latest=ghcr.io/catthehacker/ubuntu:act-latest
```

### 2. Cache các phụ thuộc

GitHub Actions hỗ trợ cache, và `act` có thể dùng cùng cơ chế đó:

**Workflow có cache:**
```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Cache pip dependencies
        uses: actions/cache@v3
        with:
          path: ~/.cache/pip
          key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
          restore-keys: |
            ${{ runner.os }}-pip-

      - name: Install Python dependencies
        run: pip install -r requirements.txt

      - name: Run tests
        run: pytest tests/
```

Khi cache trúng, phần lớn thời gian cài đặt phụ thuộc thường được bỏ qua.

### 3. Chạy job song song

Mặc định `act` chạy các job tuần tự. Có thể bật chạy song song:

```bash
# Run all jobs in parallel
act --parallel 4
```

**Workflow với nhiều job:**
```yaml
jobs:
  unit-tests:
    runs-on: ubuntu-latest
    steps:
      - run: pytest tests/unit/

  integration-tests:
    runs-on: ubuntu-latest
    steps:
      - run: pytest tests/integration/

  lint:
    runs-on: ubuntu-latest
    steps:
      - run: pylint src/
```

Thời gian thực khi đó phụ thuộc vào job chậm nhất thay vì tổng của tất cả job.

### 4. Liệt kê job mà không chạy

```bash
act --list
```

Lệnh này hiển thị các job sẽ chạy mà không thực thi chúng.

### 5. Dùng lại hoặc dựng lại container

```bash
act --reuse-containers  # Reuse running containers
act --rebuild            # Rebuild image from scratch
```

## Một ví dụ mở rộng: pipeline gene-expression

Workflow sau minh hoạ một ma trận kiểm thử nhiều phiên bản và một job bảo mật riêng.

### Tệp workflow: `.github/workflows/ml-pipeline.yml`

```yaml
name: ML Pipeline - Gene Expression Analysis
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ['3.10', '3.11', '3.12']

    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Set up Python ${{ matrix.python-version }}
        uses: actions/setup-python@v4
        with:
          python-version: ${{ matrix.python-version }}

      - name: Cache pip packages
        uses: actions/cache@v3
        with:
          path: ~/.cache/pip
          key: ${{ runner.os }}-pip-${{ matrix.python-version }}-${{ hashFiles('**/requirements.txt') }}

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt
          pip install pytest pytest-cov pytest-xdist

      - name: Lint with pylint
        run: pylint src/ --exit-zero
        continue-on-error: true

      - name: Run unit tests
        run: pytest tests/unit/ -v --cov=src --cov-report=xml

      - name: Run integration tests
        run: pytest tests/integration/ -v

      - name: Upload coverage reports
        uses: codecov/codecov-action@v3
        if: matrix.python-version == '3.12'
        with:
          files: ./coverage.xml
          flags: unittests

  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Run Bandit security check
        run: |
          pip install bandit
          bandit -r src/ -v --exit-code 0
        continue-on-error: true
```

### Chạy cục bộ

**Chạy tất cả job:**
```bash
act push
```

**Chạy một phiên bản Python cụ thể:**
```bash
act push --job test --matrix python-version=3.12
```

**Chỉ chạy job bảo mật:**
```bash
act push --job security
```

## Gỡ lỗi workflow

### Ghi log chi tiết

```bash
act -v push
```

Lệnh này in thêm chi tiết, bao gồm các lệnh Docker và biến môi trường.

### Kiểm tra tương tác

Nếu một bước thất bại, có thể kiểm tra container. Thêm một bước chẩn đoán vào workflow:

```yaml
steps:
  - run: |
      echo "Debug info:"
      env | sort
      ls -la
```

Hoặc chạy `act` với thư mục làm việc được bind vào container:

```bash
act -b  # Bind the working directory into the container
```

### Kiểm tra container sau khi thất bại

```bash
# View logs
docker ps -a

# Enter the container
docker exec -it <container_id> /bin/bash
```

### Một số vấn đề thường gặp

**"Cannot connect to Docker daemon"**
```bash
# Solution: Start Docker
sudo systemctl start docker  # Linux
open /Applications/Docker.app  # macOS
```

**"Not enough space for Docker images"**
```bash
# Solution: Clean up
docker system prune -a --volumes
```

**"Workflow runs but tests fail locally but pass on GitHub"**
```bash
# Solution: Check Python versions match
python --version
act --list  # Verify Python version in workflow
```

## Cục bộ so với cloud: một so sánh minh hoạ

Bảng dưới đây mang tính minh hoạ, không phải một phép đo chuẩn; thời gian thực phụ thuộc vào workflow, máy và mạng.

| Tác vụ | Cục bộ (`act`) | GitHub Cloud |
|------|--|--|
| Lần chạy đầu (image đã kéo sẵn) | vài chục giây | vài phút |
| Các lần chạy sau (có cache) | vài giây | vài phút |
| Vòng lặp phát triển | ngắn | dài hơn |
| Chi phí | chỉ thời gian máy | số phút runner cloud |

Với một phiên phát triển gồm nhiều vòng lặp nhỏ, tổng thời gian tiết kiệm có thể đáng kể, chủ yếu vì một workflow lỗi thường được phát hiện trước khi push.

## Một số thực hành khi dùng `act`

### 1. Kiểm thử trước khi push
```bash
# Before git push
act push
# If all pass, then:
git push origin main
```

### 2. Khớp với môi trường runner của GitHub
```bash
# Use same image as GitHub
act -P ubuntu-latest=ghcr.io/catthehacker/ubuntu:act-latest
```

### 3. Commit `.actrc`, nhưng tuyệt đối không commit `.secrets`
```bash
# .actrc (can be committed)
-P ubuntu-latest=ghcr.io/catthehacker/ubuntu:full-latest
-l
```

```bash
# .gitignore
.secrets
```

### 4. Dùng matrix cho nhiều phiên bản
```yaml
strategy:
  matrix:
    python-version: ['3.10', '3.11', '3.12']
    os: [ubuntu-latest, macos-latest]
```

### 5. Ghi lại các phụ thuộc
```bash
# requirements.txt
pytest>=7.0.0
numpy>=1.24.0
pandas>=1.5.0
scipy>=1.10.0
```

### 6. Giữ công cụ toàn cục trong Pixi

Nếu Pixi quản lý dự án, các công cụ toàn cục cũng có thể đặt ở đó:

```bash
# Install act globally with Pixi
pixi global install act

# Update act easily
pixi global upgrade act

# See all globally installed tools
pixi global list
```

**Một `.pixi.toml` cho dự án:**
```toml
[dependencies]
python = "3.12"
pytest = ">=7.0.0"
numpy = ">=1.24.0"
pandas = ">=1.5.0"

[tasks]
test = "pytest tests/ -v"
lint = "pylint src/"
ci = "act push"  # Run GitHub Actions locally
```

Sau đó cả nhóm có thể chạy:

```bash
pixi run test      # Run tests
pixi run lint      # Run linter
pixi run ci        # Run GitHub Actions locally
```

## Tóm lại

- `act` chạy các workflow GitHub Actions cục bộ, nên có thể kiểm thử một workflow trước khi push.
- Vòng phản hồi ngắn hơn so với chờ runner cloud, giúp việc lặp dễ hơn.
- Nó dựa trên Docker, nên container cục bộ gần giống runner cloud của GitHub.
- Có thể truyền secrets và biến môi trường, nên có thể kiểm thử những workflow thực tế.
- Việc chọn image, cache và chạy job song song đều ảnh hưởng tới thời gian một lần chạy cục bộ.
