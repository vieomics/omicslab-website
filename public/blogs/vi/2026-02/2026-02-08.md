Docker container được dùng rộng rãi trong bioinformatics để làm cho phân tích có thể tái lập và di động giữa các nền tảng. Bài này xem xét những vấn đề mà container giải quyết trên thực tế, cách chạy và debug công cụ bioinformatics bên trong chúng, và những cách build image hiệu quả, bao gồm với Micromamba và Pixi.

## Điều kiện tiên quyết: cài và chạy Docker

Bài này giả định Docker đã được cài và đang chạy, và tập trung vào việc dùng container cho công việc bioinformatics.

### Bắt đầu từ đây

Nếu Docker chưa được cài, tài liệu chính thức là nơi nên bắt đầu:

**https://docs.docker.com/get-started/get-docker/**

Hướng dẫn đó bao gồm:

- **Cài Docker Desktop** (macOS, Windows, Linux)
- **Kiểm tra cài đặt** bằng `docker --version`
- **Chạy container đầu tiên** bằng `docker run hello-world`
- **Kiến thức cơ bản về Docker** (image, container, registry)

### Những điều cần biết

Sau khi cài Docker, hãy kiểm tra nó hoạt động:

```bash
# Check Docker version
docker --version
# Output: Docker version 24.0.0, build 12345abc

# Run a test container
docker run hello-world
# Output: Hello from Docker! This message shows that your installation appears to be working correctly.
```

### Về bài viết này

Khi Docker đã được cài và hoạt động, bài này sẽ trình bày:

1. **Vì sao cài đặt thủ công dễ hỏng**, và container giúp ích cho tái lập như thế nào
2. **Cách dùng Docker container** để phân tích dữ liệu bioinformatics
3. **Cách build Docker image hiệu quả**
4. **Cách build container với Micromamba và Pixi**
5. **Cách tìm container dựng sẵn** trước khi tự build từ đầu

### Danh sách kiểm tra điều kiện tiên quyết

Trước khi tiếp tục, hãy kiểm tra bạn có:

- Docker đã cài (`docker --version` chạy được)
- Docker daemon đang chạy (hoặc Docker Desktop đang hoạt động)
- Có thể pull image (`docker pull hello-world` chạy được)
- Quen cơ bản với dòng lệnh
- (Tuỳ chọn) Nextflow đã cài cho các ví dụ pipeline

Nếu chưa, hãy bắt đầu với https://docs.docker.com/get-started/get-docker/ rồi quay lại đây.

## 1. Vì sao cài đặt thủ công dễ hỏng: cách cũ so với container hiện đại

Trước đây, các lab bioinformatics cài phần mềm trên server dùng chung hoặc laptop bằng những lệnh như:

```bash
sudo apt-get install samtools bwa python3
```

Trông có vẻ đơn giản, nhưng cách này tạo ra vấn đề về tái lập, di động và bảo trì:

- **Thao tác thủ công**: mỗi nhà nghiên cứu hoặc lab cài đặt hơi khác nhau. Hướng dẫn viết tay, script và ghi chú xử lý sự cố dễ bị mất, lẫn lộn hoặc lỗi thời.
- **Không tái lập được**: không có bản ghi đáng tin về việc đã cài gì, phiên bản nào, theo thứ tự nào. Theo thời gian, các bản cập nhật và xung đột phụ thuộc tích tụ, dẫn đến vấn đề "máy tôi chạy được".
- **Khó debug**: lệch phiên bản và xung đột thư viện rất khó chẩn đoán một khi môi trường đã lệch.
- **Không di động**: script hỏng trên macOS, Windows hoặc các biến thể Linux khác. Hệ thống HPC thường hạn chế quyền sudo/root, khiến cài đặt truyền thống khó khả thi.

Kết quả là cộng tác giữa các lab, tổ chức hoặc quốc gia trở nên mong manh, và việc tái lập kết quả — ngay cả trên máy của chính bạn — có thể là một thách thức.

### Cách tiếp cận hiện đại: container và công cụ cộng đồng

Phần lớn bioinformatics đã chuyển từ cài đặt thủ công sang container và trình quản lý môi trường:

- **BioConda**: hơn 8.000 gói bioinformatics có thể được cài một cách tái lập qua Conda.
- **BioContainers**: tự động sinh Docker container cho từng công cụ, có sẵn tại [quay.io/biocontainers](https://quay.io/organization/biocontainers).
    ```bash
    docker pull quay.io/biocontainers/samtools:1.15.1--h1170115_0
    ```
- **Seqera/Nextflow/nf-core**: các pipeline có định nghĩa môi trường (Conda, Docker, Singularity) được chia sẻ và chạy theo cùng cách ở mọi nơi.

Tóm lại, container và Conda giải quyết nhiều vấn đề của cài đặt thủ công, giúp cộng tác tái lập trở nên phổ biến hơn trong bioinformatics.

## 2. Dùng Docker container để phân tích dữ liệu bioinformatics

Một lợi ích của Docker là khả năng chạy trực tiếp công cụ bioinformatics, không cần cài đặt đầy đủ, trên chính bộ dữ liệu của bạn. Ví dụ dưới đây dùng FastQC, một công cụ kiểm tra chất lượng được dùng rộng rãi cho dữ liệu sequencing.

### Ví dụ: chạy FastQC từ container

1. **Pull container FastQC (chỉ cần một lần):**
   ```bash
   docker pull quay.io/biocontainers/fastqc:<version>
   # Replace <version> with the specific tag, e.g. 0.11.9--hdfd78af_1
   ```

2. **Chạy FastQC, mount thư mục dữ liệu:**
   ```bash
   docker run --rm -v "$PWD:/data" quay.io/biocontainers/fastqc:<version> fastqc /data/my_reads.fastq
   ```
   - `--rm`: tự động xoá container sau khi thoát.
   - `-v "$PWD:/data"`: mount thư mục hiện tại (chứa file FASTQ) vào container tại `/data`.
   - Container chạy FastQC, phân tích file, và ghi kết quả trở lại thư mục của bạn.

**Lợi ích chính:**
- Không cần cài đặt phần mềm hay xử lý phụ thuộc.
- Đảm bảo đúng phiên bản và môi trường.
- Phân tích có thể chia sẻ hoặc chạy lại ở bất kỳ đâu có Docker (Linux, Mac, Windows, cloud, HPC).

Cách này hoạt động với hàng nghìn container bioinformatics: thay FastQC bằng Samtools, BWA, STAR, hoặc công cụ khác.

### Chạy container tương tác

Đôi khi cần chạy công cụ hoặc khám phá tương tác bên trong container. Docker hỗ trợ điều này với cờ `-it`:

- `-i` giữ STDIN mở (nhập tương tác)
- `-t` cấp một pseudo-terminal (TTY)

**Ví dụ: mở shell tương tác bên trong container FastQC:**

```bash
docker run --rm -it -v "$PWD:/data" quay.io/biocontainers/fastqc:<version> /bin/bash
```

Bây giờ bạn đang ở trong shell của container:

```bash
fastqc /data/my_reads.fastq
ls /data
```

**Lợi ích:**
- Kiểm tra file, thử lệnh, hoặc xử lý sự cố theo thời gian thực.
- Khám phá môi trường container (phụ thuộc, công cụ đã cài).
- Môi trường vẫn tái lập được ở mỗi lần chạy.

### Debug và kiểm tra một Docker container đang chạy

Nếu một container đang chạy (có thể như một phần của pipeline hoặc tiến trình nền), Docker cho phép kết nối và debug tương tác bằng `docker exec`:

1. Liệt kê các container đang chạy:
   ```bash
   docker ps
   ```
   Ghi lại CONTAINER ID trong kết quả.

2. Mở shell bash bên trong container đang chạy:
   ```bash
   docker exec -it <CONTAINER_ID> /bin/bash
   ```
   Sau đó có thể kiểm tra file, xem log và chạy thêm lệnh bên trong container đang sống.

---

### ENTRYPOINT và ghi đè lệnh

Nhiều container chạy một công cụ cụ thể làm ENTRYPOINT mặc định; ví dụ, container FastQC tự động chạy FastQC. Bạn có thể tạm thời ghi đè ENTRYPOINT và mở một shell bằng:

```bash
docker run --rm -it --entrypoint /bin/bash quay.io/biocontainers/fastqc:<version>
```

Lệnh này mở shell tương tác ngay cả khi Dockerfile chỉ định một lệnh mặc định khác, hữu ích cho debug hoặc khám phá môi trường container.

**Tóm tắt:**
- Dùng `docker exec` để debug container đang chạy.
- Ghi đè ENTRYPOINT để có shell tương tác.
- Điều này cho phép xử lý sự cố và kiểm tra theo thời gian thực.

### Chạy container với Nextflow: xem các lệnh Docker thực tế

Khi một pipeline Nextflow chạy với Docker container, Nextflow sinh và thực thi lệnh Docker cho từng task. Hiểu những lệnh này hữu ích cho debug, profiling, và để thấy rõ pipeline đang làm gì.

#### Nextflow lưu lệnh Docker ở đâu

Nextflow tạo một cấu trúc thư mục work, trong đó mỗi task có thư mục riêng chứa:

- `.command.sh` - script shell cần thực thi
- `.command.run` - script wrapper mà Nextflow dùng để chạy task
- `.command.trace` - trace thực thi task
- `.exitcode` - exit code của task
- các file output của task

**Cấu trúc thư mục:**
```
work/
├── ab/
│   ├── abc123def456.../
│   │   ├── .command.sh
│   │   ├── .command.run
│   │   ├── .command.trace
│   │   └── ... (output files)
│   └── def789ghi012.../
│       └── ...
└── fe/
    └── 949a78b06c5fd8284aeb2f87d14f7d/
        ├── .command.sh
        ├── .command.run
        └── ... (task outputs)
```

#### Xem lệnh Docker thực tế

Để xem chính xác lệnh Docker mà Nextflow đã thực thi cho một task cụ thể:

```bash
# 1. Find your task's work directory
# For example, in the pipeline output you might see:
#   vep (ensembl-vep:115.2) [fe/949a78b...]

# 2. Navigate to that directory
cd work/fe/949a78b06c5fd8284aeb2f87d14f7d/

# 3. View the command that was executed
cat .command.run
```

#### Ví dụ: lệnh Docker của Nextflow cho VEP (Variant Effect Predictor)

Dưới đây là một ví dụ đầy đủ về cách Nextflow chạy một Docker container:

```bash
docker rm $NXF_BOXID &>/dev/null || true
docker stop $NXF_BOXID

docker run -i \
  --cpu-shares 8192 \
  --memory 14336m \
  -e "NXF_TASK_WORKDIR" \
  -e "NXF_DEBUG=${NXF_DEBUG:=0}" \
  -v <your project working directory>:<your project working directory> \
  -w "$NXF_TASK_WORKDIR" \
  -u $(id -u):$(id -g) \
  --name $NXF_BOXID \
  community.wave.seqera.io/library/ensembl-vep:115.2--90ec797ecb088e9a \
  /bin/bash <your project working directory>/work/fe/949a78b06c5fd8284aeb2f87d14f7d/.command.run nxf_trace
```

#### Phân tích lệnh Docker

Mỗi thành phần có một mục đích cụ thể:

| Component                      | Purpose                                                      |
| ------------------------------ | ------------------------------------------------------------ |
| `docker run`                   | Start a new container                                        |
| `-i`                           | Keep STDIN open (interactive)                                |
| `--cpu-shares 8192`            | Allocate CPU resources (set by Nextflow from cpus directive) |
| `--memory 14336m`              | Limit memory to 14GB (set by Nextflow from memory directive) |
| `-e NXF_TASK_WORKDIR`          | Pass Nextflow task work directory env var                    |
| `-e NXF_DEBUG=${NXF_DEBUG:=0}` | Pass debug flag                                              |
| `-v /project:/project`         | Mount project directory for input/output                     |
| `-w "$NXF_TASK_WORKDIR"`       | Set working directory inside container                       |
| `-u $(id -u):$(id -g)`         | Run as current user (file permissions)                       |
| `--name $NXF_BOXID`            | Name the container (cleanup reference)                       |
| `image:tag`                    | Container image to use                                       |
| `/bin/bash .command.run`       | Execute the task script                                      |
| `nxf_trace`                    | Nextflow tracing flag                                        |

#### Chạy lại task thất bại theo cách thủ công

Nếu một task thất bại trong Nextflow, có thể chạy lại thủ công để debug:

```bash
# 1. Navigate to the task work directory
cd work/fe/949a78b06c5fd8284aeb2f87d14f7d/

# 2. View the task script
cat .command.sh

# 3. View Nextflow's Docker wrapper
cat .command.run

# 4. Manually run the Docker command (copy from .command.run output)
# and inspect what went wrong
docker run -i \
  --cpu-shares 8192 \
  --memory 14336m \
  -e "NXF_TASK_WORKDIR" \
  -v <your project working directory>:<your project working directory> \
  -w "$NXF_TASK_WORKDIR" \
  -u $(id -u):$(id -g) \
  community.wave.seqera.io/library/ensembl-vep:115.2--90ec797ecb088e9a \
  /bin/bash <your project working directory>/work/fe/949a78b06c5fd8284aeb2f87d14f7d/.command.run

# 5. Check the exit code
cat .exitcode

# 6. View any error logs
cat .command.err  # (if exists)
cat .command.out  # (if exists)

# 7. If you run on HPC, (e.g SLURM ), run submit job
sbatch .command.run

# 8. You can debug manually by running container interactively
docker run -it -v $PWD:$PWD -w $PWD <your container> 

# 9. Modify .command.sh then inside your container, start to debug by running command directly
bash .command.sh
```

#### Các tính năng Docker chính của Nextflow

| Feature                   | How Nextflow uses it                                                     |
| ------------------------- | ------------------------------------------------------------------------ |
| **Resource limits**       | `--cpus` and `--memory` directives → `--cpu-shares` and `--memory` flags |
| **Volume mounts**         | Pipeline inputs/outputs → `-v` flags                                     |
| **User permissions**      | Current user → `-u $(id -u):$(id -g)`                                    |
| **Work directory**        | Task-specific directory → `-w "$NXF_TASK_WORKDIR"`                       |
| **Container cleanup**     | Automatic removal → `docker rm` commands                                 |
| **Environment variables** | Pipeline configuration → `-e` flags                                      |

#### Profiling và tối ưu

Việc xem các lệnh Docker thực tế có thể giúp bạn:

1. **Kiểm tra phân bổ tài nguyên:**
   ```bash
   grep "cpu-shares\|memory" work/*/*/.command.run
   ```

2. **Xác minh các volume được mount:**
   ```bash
   grep "\-v" work/ab/abc123*/.command.run
   ```

3. **Xem các image container đang dùng:**
   ```bash
   grep "docker run" work/*/*/.command.run | grep -oE "image:[^ ]+"
   ```

4. **Profiling thực thi task:**
   ```bash
   # Check how long each task took
   for dir in work/*/*/*/.command.trace; do
       echo "Task: $(dirname $dir)"
       cat "$dir"
   done
   ```

### Tóm tắt

- Nextflow tự động sinh lệnh Docker cho từng task.
- Lệnh của task nằm trong `work/<task-id>/.command.run`.
- Task thất bại có thể được kiểm tra và chạy lại thủ công.
- Hiểu những lệnh này giúp debug và tối ưu.
- Giới hạn tài nguyên từ các directive của Nextflow được chuyển thành cờ Docker.
- Mỗi task chạy biệt lập với thư mục work riêng.

## 3. Build Docker image hiệu quả cho bioinformatics

Build Docker image hiệu quả giúp image tải xuống, chạy và chia sẻ nhanh hơn.

### Best practices

- **Bắt đầu với base image nhẹ, chính thức**
  - Alpine, Debian-slim, Ubuntu LTS

- **Chỉ cài các công cụ cần thiết**
  - Tránh tiện ích và gói không cần thiết

- **Dọn cache và xoá file tạm**
  - Trong cùng bước RUN: `rm -rf /var/lib/apt/lists/*`

- **Dùng multi-stage build cho công cụ lớn hoặc cần biên dịch**
  - Build từ source trong stage builder, rồi copy binary vào image cuối gọn nhẹ

### Ví dụ tối giản: cài một công cụ

```dockerfile
FROM ubuntu:24.04
RUN apt-get update && \
    apt-get install -y --no-install-recommends samtools && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
WORKDIR /data
CMD ["/bin/bash"]
```

### Ví dụ multi-stage build: build từ source

```dockerfile
FROM ubuntu:24.04 AS builder
RUN apt-get update && apt-get install -y build-essential wget
RUN wget https://github.com/samtools/samtools/releases/download/1.18/samtools-1.18.tar.bz2 && \
    tar -xjf samtools-1.18.tar.bz2 && \
    cd samtools-1.18 && \
    ./configure --prefix=/usr/local && make && make install

FROM ubuntu:24.04
RUN apt-get update && apt-get install -y --no-install-recommends libbz2-1.0 liblzma5 zlib1g
COPY --from=builder /usr/local/bin/samtools /usr/local/bin/
WORKDIR /data
CMD ["/bin/bash"]
```

### Tối ưu thêm

- Sắp xếp danh sách gói theo thứ tự alphabet
- Dùng file `.dockerignore` để giảm kích thước build context
- Pin chính xác phiên bản công cụ/gói để tái lập

## 4. Build Docker image với Conda và Micromamba

Build Docker container từ gói Conda là một cách để tạo môi trường bioinformatics tái lập. Micromamba là một lựa chọn nhẹ thay cho Conda, phù hợp bên trong container.

### Vì sao dùng Micromamba cho Docker image?

Micromamba có một vài lợi ích thực tế so với Conda truyền thống khi build container:

- **Nhanh**: việc giải phụ thuộc được báo cáo là nhanh hơn đáng kể so với Conda.
- **Nhẹ**: dung lượng tối thiểu, phù hợp triển khai trong container.
- **Tái lập**: file lock của môi trường ghim chính xác phiên bản.
- **Được dùng rộng rãi**: phổ biến trong các pipeline bioinformatics.
- **Base image nhỏ**: image chính thức `mambaorg/micromamba` khoảng 150 MB.

### Cách tiếp cận: conda.yml + Micromamba

Thay vì viết các lệnh RUN phức tạp với chỉ định gói nội tuyến, hãy dùng file môi trường `conda.yml`.

**conda.yml:**
```yaml
name: base
channels:
  - conda-forge
  - bioconda
dependencies:
  - bioconda::fastqc=0.12.1
  - bioconda::samtools=1.18
  - bioconda::bwa=0.7.17
  - conda-forge::procps-ng
```

**Dockerfile:**
```dockerfile
FROM mambaorg/micromamba:1.5.10-noble

# Copy environment file
COPY --chown=$MAMBA_USER:$MAMBA_USER conda.yml /tmp/conda.yml

# Install packages from environment file
RUN micromamba install -y -n base -f /tmp/conda.yml \
    && micromamba clean -a -y

# Export explicit lock file for reproducibility
RUN micromamba env export --name base --explicit > environment.lock \
    && echo ">> CONDA_LOCK_START" \
    && cat environment.lock \
    && echo "<< CONDA_LOCK_END"

# Set PATH
USER root
ENV PATH="$MAMBA_ROOT_PREFIX/bin:$PATH"

WORKDIR /data
CMD ["/bin/bash"]
```

### Hiểu rõ Dockerfile

Lần lượt từng thành phần:

**1. Base image:**
```dockerfile
FROM mambaorg/micromamba:1.5.10-noble
```
- `mambaorg/micromamba` đã có Micromamba cài sẵn
- `1.5.10` là phiên bản (pin để tái lập)
- `noble` là biến thể Ubuntu 24.04 LTS
- Nhẹ hơn việc cài Conda từ đầu

**2. Copy file môi trường:**
```dockerfile
COPY --chown=$MAMBA_USER:$MAMBA_USER conda.yml /tmp/conda.yml
```
- Copy `conda.yml` của bạn vào container
- `$MAMBA_USER` là người dùng non-root do base image đặt
- Giữ đúng quyền sở hữu file

**3. Cài bằng Micromamba:**
```dockerfile
RUN micromamba install -y -n base -f /tmp/conda.yml \
    && micromamba clean -a -y
```
- `-y`: tự động xác nhận cài đặt
- `-n base`: cài vào môi trường base
- `-f /tmp/conda.yml`: dùng file môi trường
- `micromamba clean -a -y`: xoá gói đã cache, giúp giảm kích thước image

**4. Sinh file lock (để tái lập):**
```dockerfile
RUN micromamba env export --name base --explicit > environment.lock \
    && echo ">> CONDA_LOCK_START" \
    && cat environment.lock \
    && echo "<< CONDA_LOCK_END"
```
- Xuất file lock explicit với phiên bản và URL được ghim chính xác
- Các lệnh echo giúp file lock hiển thị trong build log
- File này có thể lưu lại và dùng để tái lập chính xác về sau

**5. Đặt PATH và người dùng:**
```dockerfile
USER root
ENV PATH="$MAMBA_ROOT_PREFIX/bin:$PATH"
```
- Đảm bảo binary của Micromamba nằm trong PATH
- `USER root` cần thiết cho một số theo dõi hệ thống (xem `procps-ng` bên dưới)

### Vì sao procps-ng quan trọng với Nextflow

Chú ý `conda-forge::procps-ng` trong các phụ thuộc. Lý do là:

```yaml
dependencies:
  - conda-forge::procps-ng
```

Nextflow dùng các công cụ của `procps-ng` (như `ps`, `top`) để theo dõi:

- Mức dùng CPU
- Mức tiêu thụ bộ nhớ
- Trạng thái tiến trình

Nếu thiếu chúng, Nextflow không thể theo dõi mức dùng tài nguyên của task. Nên đưa chúng vào container bioinformatics.

### Ví dụ đầy đủ với nhiều công cụ

Một ví dụ đầy đủ hơn với nhiều công cụ bioinformatics:

**conda.yml:**
```yaml
name: base
channels:
  - conda-forge
  - bioconda
dependencies:
  - bioconda::fastqc=0.12.1
  - bioconda::samtools=1.18
  - bioconda::bwa=0.7.17
  - bioconda::bcftools=1.18
  - bioconda::picard=3.0.0
  - conda-forge::procps-ng
  - conda-forge::parallel
```

**Dockerfile:**
```dockerfile
FROM mambaorg/micromamba:1.5.10-noble

COPY --chown=$MAMBA_USER:$MAMBA_USER conda.yml /tmp/conda.yml

RUN micromamba install -y -n base -f /tmp/conda.yml \
    && micromamba install -y -n base conda-forge::procps-ng \
    && micromamba env export --name base --explicit > environment.lock \
    && echo ">> CONDA_LOCK_START" \
    && cat environment.lock \
    && echo "<< CONDA_LOCK_END" \
    && micromamba clean -a -y

USER root
ENV PATH="$MAMBA_ROOT_PREFIX/bin:$PATH"

WORKDIR /data
CMD ["/bin/bash"]
```

### Build và dùng container của bạn

**1. Build image:**
```bash
docker build -t myregistry.com/bioinformatics/biotools:1.0 .
```

**2. Kiểm tra cục bộ:**
```bash
docker run --rm -v "$PWD:/data" myregistry.com/bioinformatics/biotools:1.0 \
    fastqc /data/sample.fastq
```

**3. Push lên registry:**
```bash
docker push myregistry.com/bioinformatics/biotools:1.0
```

**4. Dùng trong Nextflow:**
```groovy
process FASTQC {
    tag "${meta.id}"
    label 'process_medium'

    conda "${moduleDir}/environment.yml"
    container "${ workflow.containerEngine == 'singularity' && !task.ext.singularity_pull_docker_container ?
        'https://depot.galaxyproject.org/singularity/fastqc:0.12.1--hdfd78af_0' :
        'biocontainers/fastqc:0.12.1--hdfd78af_0' }"

    input:
    tuple val(meta), path(reads)

    output:
    tuple val(meta), path("*.html"), emit: html
    tuple val(meta), path("*.zip") , emit: zip
    path  "versions.yml"           , emit: versions

    when:
    task.ext.when == null || task.ext.when

    script:
    def args          = task.ext.args ?: ''
    def prefix        = task.ext.prefix ?: "${meta.id}"
    // Make list of old name and new name pairs to use for renaming in the bash while loop
    def old_new_pairs = reads instanceof Path || reads.size() == 1 ? [[ reads, "${prefix}.${reads.extension}" ]] : reads.withIndex().collect { entry, index -> [ entry, "${prefix}_${index + 1}.${entry.extension}" ] }
    def rename_to     = old_new_pairs*.join(' ').join(' ')
    def renamed_files = old_new_pairs.collect{ _old_name, new_name -> new_name }.join(' ')

    // The total amount of allocated RAM by FastQC is equal to the number of threads defined (--threads) time the amount of RAM defined (--memory)
    // https://github.com/s-andrews/FastQC/blob/1faeea0412093224d7f6a07f777fad60a5650795/fastqc#L211-L222
    // Dividing the task.memory by task.cpu allows to stick to requested amount of RAM in the label
    def memory_in_mb = task.memory ? task.memory.toUnit('MB') / task.cpus : null
    // FastQC memory value allowed range (100 - 10000)
    def fastqc_memory = memory_in_mb > 10000 ? 10000 : (memory_in_mb < 100 ? 100 : memory_in_mb)

    """
    printf "%s %s\\n" ${rename_to} | while read old_name new_name; do
        [ -f "\${new_name}" ] || ln -s \$old_name \$new_name
    done

    fastqc \\
        ${args} \\
        --threads ${task.cpus} \\
        --memory ${fastqc_memory} \\
        ${renamed_files}

    cat <<-END_VERSIONS > versions.yml
    "${task.process}":
        fastqc: \$( fastqc --version | sed '/FastQC v/!d; s/.*v//' )
    END_VERSIONS
    """

    stub:
    def prefix = task.ext.prefix ?: "${meta.id}"
    """
    touch ${prefix}.html
    touch ${prefix}.zip

    cat <<-END_VERSIONS > versions.yml
    "${task.process}":
        fastqc: \$( fastqc --version | sed '/FastQC v/!d; s/.*v//' )
    END_VERSIONS
    """
}
```

### Lợi ích của cách tiếp cận này

| Feature             | conda.yml + Micromamba  | Traditional Conda Dockerfile |
| ------------------- | ----------------------- | ---------------------------- |
| **Build speed**     | Fast                     | Slow                         |
| **Image size**      | Small for typical tools  | Larger                       |
| **Reproducibility** | Explicit lock file      | Dependency drift possible    |
| **Version pinning** | Easy in YAML            | Inline in Dockerfile         |
| **Readability**     | Clear, readable YAML    | Complex RUN statements       |
| **Channel support** | Multiple channels       | Limited                      |
| **Maintenance**     | Update conda.yml easily | Rebuild entire Dockerfile    |

### Lưu và chia sẻ file lock explicit

File `environment.lock` sinh ra có thể lưu trong dự án:

```bash
# Extract from build output and save
docker build . 2>&1 | grep -A 1000 "CONDA_LOCK_START" | grep -B 1000 "CONDA_LOCK_END" > environment.lock
```

Về sau, có thể tái lập chính xác môi trường:

```bash
# Rebuild from locked versions
micromamba install -y -n base --file environment.lock
```

### Pixi: một lựa chọn mới hơn cho container dựa trên Conda

Pixi là công cụ mới hơn, kết hợp các khía cạnh của Conda, Mamba và quản lý file lock. Nó ngày càng được dùng trong bioinformatics để build container tái lập.

**Vì sao dùng Pixi?**
- **Nhanh**: việc giải phụ thuộc được báo cáo là nhanh.
- **File lock tự động**: file lock được tạo tự động, không cần xuất thủ công.
- **Tái lập một bước**: một công cụ lo cả cài đặt lẫn tái lập.
- **Đa nền tảng**: hoạt động trên nhiều kiến trúc và hệ thống khác nhau.
- **Được thiết kế với containerization trong đầu.**

**Ví dụ Dockerfile với Pixi:**

```dockerfile
ARG PIXI_VERSION=0.63.2
ARG BASE_IMAGE=debian:bookworm-slim

FROM --platform=linux/amd64 ubuntu:24.04 AS builder
ARG PIXI_VERSION
RUN apt-get update && apt-get install -y curl
RUN curl -Ls \
    "https://github.com/prefix-dev/pixi/releases/download/v${PIXI_VERSION}/pixi-$(uname -m)-unknown-linux-musl" \
    -o /pixi && chmod +x /pixi
RUN /pixi --version

FROM --platform=linux/amd64 $BASE_IMAGE

# Add appuser with UID 1000
RUN useradd -u 1000 -m -s /bin/bash appuser
USER appuser
WORKDIR /home/appuser

# Copy pixi from builder
COPY --from=builder --chown=appuser:appuser --chmod=0555 /pixi /usr/local/bin/pixi

# Set up pixi with conda channels
ENV PATH="/home/appuser/.pixi/bin:${PATH}"
RUN pixi config set default-channels '["conda-forge", "bioconda"]' --global

# Install tools using pixi
RUN pixi global install fastqc=0.12.1 samtools=1.18 bwa=0.7.17

# Clean cache
RUN pixi clean cache -y

WORKDIR /data
CMD ["/bin/bash"]
```

**Các tính năng chính của Pixi trong Dockerfile:**
- **Multi-stage build**: stage builder cài Pixi; stage cuối gọn nhẹ
- **Quản lý người dùng**: `appuser` non-root để tăng bảo mật
- **Thiết lập kênh toàn cục**: cấu hình sẵn kênh conda-forge và bioconda
- **Cài gói trực tiếp**: `pixi global install` cài và ghim phiên bản
- **File lock tự động**: file lock được sinh ngầm định, đảm bảo tái lập
- **Dọn cache**: `pixi clean cache -y` xoá file tạm

**So sánh các công cụ container:**

| Feature              | Conda           | Micromamba     | Pixi         |
| -------------------- | --------------- | -------------- | ------------ |
| **Speed**            | Baseline        | Faster         | Fast         |
| **Lock file**        | Manual export   | Manual export  | Automatic    |
| **Image size**       | Large           | Small          | Small        |
| **Reproducibility**  | Good            | Strong         | Strong       |
| **Complexity**       | High            | Medium         | Low          |
| **Learning curve**   | Steep           | Medium         | Low          |
| **Production-ready** | Yes             | Yes            | Emerging     |

**Tóm tắt:**
- Dùng `conda.yml` với Micromamba cho các workflow đã được kiểm chứng.
- Dùng Pixi cho dự án mới hưởng lợi từ file lock tự động.
- Đưa `procps-ng` vào để tương thích Nextflow, bất kể công cụ nào.
- Sinh và giữ file lock explicit để tái lập.
- Pin chính xác phiên bản để tránh lệch phụ thuộc.
- Hỗ trợ nhiều kênh (conda-forge + bioconda) xử lý được các phụ thuộc phức tạp.

## 5. Tìm container dựng sẵn trước khi build từ đầu

Trước khi dành thời gian build Docker image từ đầu, hãy kiểm tra xem công cụ đã có trong registry container công khai chưa. Nhiều công cụ bioinformatics đã có container dựng sẵn, được bảo trì, sẵn sàng dùng.

### Chiến lược tìm container

Một thứ tự thực tế là:

1. **Kiểm tra BioContainers** (https://biocontainers.pro/registry) - registry bioinformatics toàn diện nhất
2. **Kiểm tra Seqera Containers** (https://seqera.io/containers/) - kết hợp nhiều công cụ, build hiện đại
3. **Tự build** - chỉ khi công cụ không tồn tại

### 1. BioContainers (nguồn chính)

**BioContainers** build và bảo trì Docker container cho các gói bioconda. Đây là điểm dừng đầu tiên phổ biến cho công cụ bioinformatics.

**URL:** https://biocontainers.pro/registry

**Cách tìm và dùng một công cụ:**

```bash
# Search for FastQC
docker search quay.io/biocontainers/fastqc

# Pull a specific version
docker pull quay.io/biocontainers/fastqc:0.12.1--hdfd78af_1

# Run the tool
docker run --rm -v "$PWD:/data" quay.io/biocontainers/fastqc:0.12.1--hdfd78af_1 \
    fastqc /data/sample.fastq
```

![biocontainer](./imgs/biocontainer_container_registry.png)

**Ưu điểm:**
- Cập nhật tự động khi gói bioconda cập nhật
- Container một công cụ (sạch, tối giản)
- Ổn định và được kiểm thử rộng rãi
- Có sẵn cho hầu hết công cụ bioinformatics
- Miễn phí và truy cập công khai

**Hạn chế:**
- Một công cụ mỗi image (không kết hợp nhiều công cụ)
- Phải tự điều phối nhiều container cho một pipeline

**Ví dụ với nhiều công cụ trong một workflow:**

```bash
# Align reads with BWA
docker run --rm -v "$PWD:/data" quay.io/biocontainers/bwa:0.7.17--h5bf99c6_8 \
    bwa mem /data/ref.fa /data/reads.fq > /data/aligned.sam

# Sort BAM with Samtools
docker run --rm -v "$PWD:/data" quay.io/biocontainers/samtools:1.18--hd87286a_0 \
    samtools sort /data/aligned.sam > /data/aligned.bam
```

### 2. Seqera Containers (cũng hỗ trợ image nhiều công cụ)

**Seqera Containers** cung cấp một registry các container dựng sẵn, thường kết hợp nhiều công cụ, phù hợp với workflow phức tạp.

**URL:** https://seqera.io/containers/

**Cách tìm và dùng container:**

1. Truy cập https://seqera.io/containers/
2. Tìm công cụ của bạn
3. Thêm nhiều công cụ nếu cần (ví dụ `fastqc` + `samtools` cùng nhau)
4. Chọn kiến trúc (linux/amd64 hoặc linux/arm64)
5. Lấy tham chiếu container

**Ví dụ:**
```bash
# Pull a multi-tool container
docker pull wave.seqera.io/library/fastqc:0.12.1-samtools_1.18

# Or use in Nextflow
process analyzeReads {
    container 'wave.seqera.io/library/fastqc:0.12.1-samtools_1.18'
    script:
    '''
    fastqc input.fastq
    samtools view input.bam
    '''
}
```

![seqera_container](./imgs/seqera_container_registry.png)

**Ưu điểm:**
- Kết hợp nhiều công cụ trong một image
- Hạ tầng hiện đại
- Giao diện web để tìm kiếm
- Sinh file lock tự động
- Hỗ trợ đa kiến trúc

**Hạn chế:**
- Ít tổ hợp dựng sẵn hơn BioContainers
- Phụ thuộc vào hạ tầng của Seqera

### 3. Khi nào nên build từ đầu

Tự build container là hợp lý khi:

1. **Công cụ không tồn tại** trong bất kỳ registry công khai nào
2. **Phiên bản không có sẵn** và bạn cần bản cũ hơn hoặc mới hơn
3. **Cần chỉnh sửa tuỳ biến** (thêm phụ thuộc, script)
4. **Cần tối ưu hiệu năng** cho phần cứng cụ thể

**Kịch bản ví dụ:**
```bash
# Check if tool exists
docker pull quay.io/biocontainers/myraretool:latest  # Not found

# Check Seqera Containers
# Visit https://seqera.io/containers/ - (tool not found)

# → NOW you build it yourself using the Section 4 approach
docker build -t myregistry.com/myraretool:1.0 .
docker push myregistry.com/myraretool:1.0
```

### Tham chiếu nhanh: tìm từng công cụ ở đâu

| Tool type                                               | Primary location                         | Alternative                   | Fallback       |
| ------------------------------------------------------- | ---------------------------------------- | ----------------------------- | -------------- |
| **Common bioinformatics** (FastQC, SAMtools, BWA, etc.) | https://biocontainers.pro/registry       | https://seqera.io/containers/ | Build yourself |
| **R/Bioconductor packages**                             | https://biocontainers.pro/registry       | https://seqera.io/containers/ | Build yourself |
| **Python bioinformatics**                               | https://biocontainers.pro/registry       | https://seqera.io/containers/ | Build yourself |
| **Specialized tools**                                   | https://biocontainers.pro/registry first | GitHub releases               | Build yourself |

### Workflow thực tế: tìm → pull → dùng

```bash
#!/bin/bash
# 1. Search for tool in BioContainers
TOOL="fastqc"
VERSION="0.12.1"
echo "Searching for $TOOL:$VERSION in BioContainers..."
docker pull quay.io/biocontainers/$TOOL:$VERSION--* 2>/dev/null && \
    echo "Found in BioContainers!" && \
    exit 0

# 2. Try Seqera Containers
echo "Trying Seqera Containers..."
# (Check https://seqera.io/containers/ manually or via API)

# 3. Build yourself
echo "Not found in public registries. Building from scratch..."
# Use the Section 4 approach with Micromamba or Pixi
docker build -t myregistry.com/$TOOL:$VERSION .
```

### Best practices khi dùng container dựng sẵn

1. **Pin chính xác phiên bản:**
   ```bash
   ✓ Good: docker pull quay.io/biocontainers/samtools:1.18--hd87286a_0
   ✗ Bad:  docker pull quay.io/biocontainers/samtools:latest
   ```

2. **Dùng build digest trong Nextflow:**
   ```groovy
   process myTask {
       // Include digest for reproducibility
       container 'quay.io/biocontainers/samtools:1.18--hd87286a_0@sha256:abc123...'
       script: 'samtools view input.bam'
   }
   ```

3. **Giữ cache cục bộ để làm việc offline:**
   ```bash
   docker pull quay.io/biocontainers/samtools:1.18--hd87286a_0
   docker tag quay.io/biocontainers/samtools:1.18--hd87286a_0 \
       myregistry.com/samtools:1.18
   docker push myregistry.com/samtools:1.18
   ```

### Tóm tắt: cây quyết định chọn container registry

```
Do you need a bioinformatics tool in a container?
```
